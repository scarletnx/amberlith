## Why an assembler

The Switch 2's graphics unit runs 128-bit instructions, which ScarletNX calls SM86, and a program's stages reach
NVN as that code with a control section beside it. uam, the one compiler a homebrew program has, writes the
Switch's code. So the probe's Switch 2 programs are written by hand, one instruction a line, and
`tools/sm86asm.py` makes the two things NVN takes a stage as. Nothing here is compiled from a shading language:
what a line says is what the graphics unit is given.

## Where an encoding comes from

- **The opcode** of every instruction, and the forms it has, are read from `tools/sm86/sm86.decode`: ScarletNX's
  own decode table (`src/nx/gpu/shader/sm86.decode`), byte for byte, at the commit `tools/sm86/PIN` names. Its
  rows are a name, the three bits of a form and the nine of an opcode; the assembler looks a mnemonic up there and
  refuses a form the table does not hold. A test holds the copy to the pin's hash.
- **The operands' places** are the assembler's: the common ones (the guard, the destination, the three sources of
  an arithmetic instruction and which form puts which where) and each instruction's own. They follow ScarletNX's
  `sm86.h`, its decoder and its translator, which take them from Mesa's NAK (`sm70_encode.rs`) and from the
  encodings its table's comments cite.

So the assembler and ScarletNX share the table: see [the round trip](#the-round-trip-and-what-it-proves) for what
that leaves to be proven, and by what.

## Using it

```sh
tools/sm86asm.py program.sm86 --code program.bin --control program.ctl [--list]
```

`--list` prints each instruction as it was assembled, with its two words. A line the assembler does not take ends
it with exit status 1, the line's number and the value it was given; nothing is written then.

## A source file

ASCII, one instruction a line, `;` to the end of a line a comment. Directives first:

| Directive | Stage | What it sets |
| --- | --- | --- |
| `.stage compute\|vertex\|fragment\|mesh\|task` | all | the program's stage, before any other directive |
| `.const VALUE...` | all | words of the program's own constants, constant buffer 1 |
| `.local X Y Z` | compute | the block, each 1 to 1024 |
| `.shared BYTES` | compute | its shared memory |
| `.out NAME...` | vertex, mesh | the outputs written: `position`, `generic0` to `generic31`, with `.xyzw` components |
| `.in NAME...` | fragment | the inputs read, the same names |
| `.targets N` | fragment | the colour targets written, 1 to 8 (1) |
| `.threads N` | mesh, task | the workgroup's invocations, 1 to 32: one warp |
| `.payload BYTES` | mesh, task | the task payload's bytes |
| `.vertices N`, `.primitives N` | mesh | the most it writes, each 1 to 256 |
| `.after-task 0\|1` | mesh | whether a task program launches it |

Then the instructions: an optional `label:`, an optional guard (`@P0`, `@!P0`), the mnemonic with its modifiers
after dots, and the operands after commas. The program has to end on an `EXIT` or a `BRA` every lane takes; the
assembler adds the branch to itself that follows every program.

### Operands

| Written | Is |
| --- | --- |
| `R0` to `R254`, `RZ` | a register, the zero register |
| `UR0` to `UR62`, `URZ` | a uniform register |
| `P0` to `P6`, `PT`, `!P0` | a predicate, the true one, a negated one |
| `-R1`, `\|R1\|`, `-\|R1\|` | a source negated, its absolute value, both: where the instruction has them |
| `12`, `0x1f`, `-3`, `1.5f` | a number: a float ends in `f` and is its 32 bits |
| `c[3][0x10]` | a word of a constant buffer, bank and byte offset |
| `c[1][R2 + 0x10]` | the same indexed by a register, `LDC`'s |
| `a[0x80]` | an attribute's address |
| `[R0 + UR4 + 0x100]` | memory: a register, a uniform register pair, an offset |

### The instructions

The arithmetic ones take a destination and two or three sources, of which the second and third may be a register,
a number, a constant buffer word or a uniform register; which form the table has to hold follows from that.

| Mnemonic | Operands | Modifiers |
| --- | --- | --- |
| `MOV` | `Rd, b` | |
| `FADD`, `FMUL` | `Rd, a, b` | `.FTZ`, `.SAT`, a rounding `.RN` `.RM` `.RP` `.RZ` |
| `FFMA` | `Rd, a, b, c` | the same |
| `FMNMX` | `Rd, a, b, P` (the lesser where P holds) | `.FTZ` |
| `FSETP` | `Pd, Pd2, a, b, P` | a comparison (`.LT` `.EQ` `.LE` `.GT` `.NE` `.GE` `.NUM` `.NAN` and their unordered `.LTU` to `.GEU`), `.AND` `.OR` `.XOR`, `.FTZ` |
| `ISETP` | `Pd, Pd2, a, b, P` | `.LT` to `.GE`, `.S32` or `.U32`, `.AND` `.OR` `.XOR` |
| `IADD3`, `IMAD` | `Rd, a, b, c` | |
| `IMNMX` | `Rd, a, b, P` | `.S32` or `.U32` |
| `SHF` | `Rd, low, shift, high` | `.L` or `.R`, `.S32` `.U32` `.S64` `.U64`, `.W`, `.HI` |
| `LOP3` | `Rd, a, b, c, table` | `.LUT` |
| `SEL` | `Rd, a, b, P` | |
| `I2F` | `Rd, b` | `.S32` or `.U32`, a rounding |
| `F2I` | `Rd, b` | `.S32` or `.U32`, `.NEAREST` `.FLOOR` `.CEIL` `.TRUNC`, `.FTZ` |
| `S2R` | `Rd, NAME` | the names: `SR_LANEID`, `SR_TID.X` `.Y` `.Z`, `SR_CTAID.X` `.Y` `.Z` |
| `ULDC` | `URd, c[bank][offset]` | a size (`.32`, `.64` for a pair) |
| `LDC` | `Rd, c[bank][R + offset]` | a size |
| `LDG`, `STG` | `Rd, [R + UR + offset]` / `[R + UR + offset], Rs` | `.E`, a size (`.U8` `.S8` `.U16` `.S16` `.32` `.64`) |
| `IPA` | `Rd, a[address]` | `.CENTROID`, `.CONSTANT` |
| `ALD`, `AST` | `Rd, a[address]` / `a[address], Rs` | the words, `.32` to `.128` |
| `ISBERD`, `ISBEWR` | `Rd, [R + offset]` / `[R + offset], Rs` | `.MAP` `.PATCH` `.PRIM` `.ATTR`, `.U8` `.U16` `.B32`, `.SKEW`, `.O` |
| `BRA` | `label` | |
| `EXIT`, `KILL`, `NOP` | | |

An instruction's rounding and its flush to zero are written on every line that wants them: nothing is implied by
the stage. A compiler for the Switch flushes in fragment programs and not in compute ones, and a reference on the
processor has to do as the program says.

A 32-bit shift right of a signed word is `SHF.R.S32.HI Rd, RZ, shift, Rs`: the instruction shifts the pair of its
first and third sources, and `.HI` takes the upper word of the result.

### Fields by hand

After ` ! `, fields as `LOW:BITS=VALUE` are written over whatever the line made: for a field the assembler has no
name for, such as the scheduling a compiler adds (`EXIT ! 105:4=5 109:1=1` is the `EXIT` a console's compiler
writes, with its stall of five cycles and its yield).

## What it writes

- **The code**, a multiple of 0x100 bytes: for a graphics stage the program header of 32 words (the first names
  the stage, and the maps say which words of which attributes it reads and writes), then the instructions, 16
  bytes each, the branch to itself, and the constants on the next 0x100 boundary. A compute program has no header.
- **The control section**, 0xD8 bytes, as ScarletNX reads an Ounce game's: the magic `0x98761234`, `0xC9` where a
  Switch's has 1, format 11, at 0x38 the code's bytes, at 0x3C the constants' bytes and at 0x40 their offset, at
  0x44 the code area's bytes, the stage in the halfword at 0x56, and from 0x58 a compute program's block and at
  0x64 its shared memory, or a mesh or task program's invocations and payload, whether a task program launches
  it, and the most vertices and primitives.

## What a program reads and writes

What follows is ScarletNX's reading of an Ounce game's programs (its `docs/platforms/nx/ounce.md`), which is all a
program of the probe's has to agree with: no console runs these.

### A compute program

- Its place in the dispatch: `SR_TID.X` to `.Z` in its block, `SR_CTAID.X` to `.Z` the block's.
- Constant buffer 0 is the driver's table: the dispatch's grid at 0x200, uniform buffers from 0x210 and storage
  buffers from 0x310, 16 bytes each, a 64-bit address then a size. A storage buffer is reached by its address:
  `ULDC.64 UR4, c[0][0x310]`, then `LDG.E` and `STG.E` at `[R + UR4 + offset]`.
- Uniform buffer slot r is constant buffer 3 + r, as on the Switch.

### A mesh program

Every output, input and count goes through one buffer, with `ISBERD` and `ISBEWR`:

| What | Instruction |
| --- | --- |
| the workgroup's index (a task program, or a mesh program with none) | `ISBERD.ATTR.SKEW.B32 Rd, [RZ + 0x0]` |
| the same, in a mesh program a task program launched | `ISBERD.ATTR.B32 Rd, [RZ + 0x0]` |
| a task program's payload, from byte 0x10 | `ISBEWR.ATTR.O.B32 [R + 0x10], Rs`, read back with `ISBERD.ATTR.B32` |
| the mesh groups a task program launches | `ISBEWR.ATTR.O.B32 [RZ + 0x4], Rs` |
| word k of vertex v's outputs | `ISBEWR.ATTR.SKEW.O.B32` at `(v / 32) * G + (v % 32) * 4 + k * 0x80`, with `G` 0x80 times the words a vertex has, in the order of the output map |
| index i of primitive p | `ISBEWR.MAP.O.U8` at `4 + 3 p + i` |
| the primitives written | `ISBEWR.MAP.O.B32 [RZ + 0x3], Rs` |

A workgroup is one warp: at most 32 invocations, `SR_LANEID` the invocation. The header's first word is a vertex
program's for a task program and for a mesh program with none, and a tessellation evaluation program's for a mesh
program a task program launches; the control section's stage tells them apart.

### The warp's matrix instructions

`HMMA`, `LDSM` and `MOVM` multiply and accumulate matrices of half floats held across a warp's lanes, in compute
programs. The assembler does not write them yet. When it does, what a case can hold them to is narrower than for
any other instruction: no public description gives their arithmetic, ScarletNX's translator is the only reading of
it there is (its `shader.h`, the `hmma_` settings, and `tests/shader_sm86.c`), and a case that passes says the
translator agrees with itself on the processor's side of the same reading.

## The round trip, and what it proves

A program assembled here is read back by ScarletNX's decoder, which is another program reading the same table:
`snx-sm86 program.bin --list` names each instruction, its form, its destination and its sources, and with
`--translate --validate` translates the program and has the result validated.

- **It proves** the assembler put the operands where ScarletNX's decoder looks for them: the two are written
  apart, and a field in the wrong place comes back as another instruction or another operand.
- **It does not prove** the table. Both sides read the same rows, so a row that is wrong about the hardware is
  wrong on both, and the round trip passes.
- **Whether the table is right** is for a program's pixels to say: a case draws with the program and holds what
  comes out to what the processor works out for the same instructions. And there the reach ends at ScarletNX: no
  console runs a homebrew program of this kind, so a pass says ScarletNX agrees with the probe's reading, not
  that the hardware does.

## Tests

`tools/test_sm86asm.py`, run by `make -f host.mk host-run`: the copy of the table against its pin; whole programs
(compute, vertex, fragment, mesh) against the words ScarletNX's own tests build for the same instructions, set
one field at a time with none of the assembler's code; a console compiler's last two instructions, as ScarletNX's
documentation records them; each form of the arithmetic instructions and each modifier at its bits; and what is
refused, each with the line and the value.
